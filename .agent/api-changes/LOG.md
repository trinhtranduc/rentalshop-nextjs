# API change log (impact tracking)

Every change to the API surface lands here: a route, a package the API uses (`packages/database`, `utils`,
`constants`, `auth`, `validation`), a business rule the API enforces, `prisma/`, or an API env var.
Rule and procedure: `AGENTS.md` → API compatibility, skill `api-compat-review`.

- **One row per change**, added in the PR that makes it (planned rows may be added by the issue).
- **Old iOS / Old Android / Web** = what the installed builds on `main-real` do with the change, with the
  `file:line` you read. "Not verified" is allowed; a guess is not.
- **Status**: `planned` (issue open) → `dev` (merged to dev) → `main-real` (released, with the release PR).
  `release-review` updates the status and fills **Checked after release**.
- Never delete a row. A reverted change gets a new row that says so.
